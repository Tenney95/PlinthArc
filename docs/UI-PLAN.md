# PlinthArc v0.1 前端实施方案

2026 年 11 月 27 日。当前试跑提供左侧工具栏、GPUCanvas 节点画布与小地图、模型与产物目录设置和历史。支持把已登记的 Z-Image-Turbo 模型节点连接到图像生成节点。生图请求沿用已有的原生操作契约，各节点的草稿和视图保存在本机浏览器或 WebView。[网页和桌面启动方式](QUICKSTART.md#从-arc-界面生成)

PlinthArc 打开后进入创作页。用户选择模型和生成方式，填入所需素材，提交后在同一页看进度和结果。首版面向开放权重图像生成及 MiniMax H3 视频。H3 的末帧、参考视频、参考音频等输入按已验证的配置开放。[运行时规范](SPEC.md) · [项目实施方案](PLAN.md)

## 1. 页面和工作区

| 入口 | 主视图 | 用户能完成的操作 |
|---|---|---|
| 创作 | 左侧结果画布，右侧生成面板 | 选择文生图、参考图编辑、H3 文生视频或图生视频。查看进度、预览结果、使用上一次有效参数。 |
| 模型库 | 按模型分组的清单与选中项详情 | 查看权重变体、组件、占用、支持的生成方式和实机验证情况。查看外部权重的登记状态及重连方法。 |
| 历史 | 按时间排列的运行记录 | 按任务类型和状态筛选，查看实际参数、种子、错误阶段和产物。以该次参数新建草稿。 |

创作页窄屏时从左右布局变为上下布局，生成按钮保留在参数区底部。画布工具只提供复位视图、缩放和选中。空画布保留一条与当前状态相关的入口，例如没有模型时打开模型库，有可运行模型时开始填写。历史页提供常规列表，可用键盘完成选中、打开详情和预览。

当前界面采用 AI Canvas UI Kit 的浅色配色和控件尺寸。左侧工具栏、节点菜单、小地图与缩放栏采用相同的浮层样式。模型、缩放比例和渲染方式共用自定义下拉，展开时避开画布裁剪。按钮、表单、设置弹窗、状态提示和结果卡片由 PlinthArc 内的样式模块提供。图像入口使用图像语义色。状态同时显示文字，输入错误留在字段旁，快捷操作保留可见焦点。

每张结果卡片使用固定的运行 ID 与产物 ID。显示缩略图、状态和必要的媒体信息。选中卡片展开详细信息，视频在普通 DOM 播放器中打开。成功获得的实际尺寸、帧率、时长和音轨来自 Rust 返回的产物元数据。

## 2. 从选择模型到取得结果

### 第一次打开

计划由 `plintharc serve` 打印本地入口。页面加载后读取设备配置和已登记模型，已打开的页面遇到服务中断时显示连接状态与重试入口。没有模型时引导进入模型库。模型库展示推荐清单、组件来源和许可链接。下载或登记完成后，用户可以回到原来的草稿继续操作。

已有权重通过 CLI 原地登记。模型库提供与所选型号对应的登记或重连说明，完成后可刷新索引。权重目录由本地 CLI 接收，页面用模型包摘要查询登记记录。参考素材通过浏览器文件选择器上传，提交时使用资产 ID。多个模型共用组件时，托管库的磁盘占用按唯一组件计算，外部组件单独标记。详情展示组件被哪些包引用。

### 生成面板

基础区域按模型、操作、提示词、参考素材、输出规格排列。采样器、步数和种子等字段在该配置支持时显示于「高级参数」。参数类型、可用选项、默认值、范围和素材顺序均来自后端能力描述。

| 操作 | 基础字段 | 交互 |
|---|---|---|
| 文生图 | 提示词、尺寸 | 支持的尺寸来自当前配置。切换比例后显示将提交的实际像素尺寸。 |
| 参考图编辑 | 编辑指令、参考图、输出规格 | 区分参考图的角色和顺序，清楚提示缺少必选素材。 |
| H3 文生视频 | 提示词、画幅、帧数与帧率 | 提交前按帧数与帧率显示预计时长。固定帧率显示为只读。 |
| H3 图生视频 | 首帧、提示词、输出规格 | 通过验证的配置可额外显示末帧。首帧和末帧分别预览并可替换。 |
| H3 多参考视频 | 提示词、有序的参考项、输出规格 | 仅在当前配置开放时显示。按配置显示统一有序列表或按图片、视频、音频分组，分别标明组内顺序和超量项。 |

切换模型或操作时保留双方语义一致且仍有效的字段。其他已有输入保持在当前草稿并标明需要调整，检查通过后才可提交。结果详情展示实际种子和使用该值的操作。历史的「使用参数」创建可编辑草稿，缺失的权重或素材按现在的状态重新提示。

### 检查、提交和恢复

点一次「生成」即可进入检查并提交。浏览器负责必填项和字段格式，Rust 在接受任务前重新检查模型文件、版本、输入、设备、资源和输出权限。预检结果对应当前请求。模型、参数或素材变化后清除旧的通过状态。检查失败指向字段、模型组件或设备，并给出相应入口。显存预检通过仍可能因运行期间资源变化而失败，任务卡片保留准确的失败阶段。

浏览器发出生成请求前在标签页会话中保存请求键及对应请求，收到明确回执后清理。Rust 在启动推理前持久记录请求键、请求摘要与运行 ID。同键同请求取回原运行 ID，同键不同请求返回冲突。提交响应中断时先显示「正在确认提交」，使用原键重试。页面刷新后仍可确认提交并读取运行历史。

| 状态场景 | 页面行为 |
|---|---|
| 正在检查或提交 | 显示当前阶段，暂时禁用同一个提交按钮，保留输入内容。 |
| 运行中 | 显示加载、采样、解码、封装或发布阶段。有实际进度时显示百分比，否则显示阶段和耗时。 |
| 等待取消 | 显示已请求停止。Rust 确认计算停止后才显示已取消。 |
| 服务暂时断开 | 保留最近一次已确认的任务状态，显示正在重新连接。 |
| 等待交付 | 显示已保留完整产物，按原运行 ID 重试交付。 |
| 已中断或失败 | 保留参数、运行 ID 与失败阶段。用户另行选择重新生成。 |
| 完成 | 仅在后端确认产物可读后显示预览与下载。历史详情可查看实际参数和模型变体。 |

## 3. 工作区与 GPUCanvas

前端放在同仓 `ui/`，使用 React、TypeScript 和 Vite。结果工作区以 `gpucanvas/react` 实现。用 `GpuCanvas` 和 `CanvasNode` 放置缩略图和任务卡片。画布位置、选择和缩放由应用维护，切换渲染方式或重新挂载时恢复视图。表单、导航、错误消息和媒体播放器在画布外使用常规 DOM。

首轮验证基于 `gpucanvas@0.6.0`。默认用 `mode="auto"`。GPU 初始化要求实际可用的 WebGPU 与 HTML-in-Canvas。通过 `onReady` 获取实例并读取实际 `mode`。切换为 `mode="dom"` 时重建画布实例，再恢复相机和选中项。保留手动切换入口，Chrome 157+ 验证 GPU 路径，Safari 验证 DOM 路径。两条路径须支持选中、平移、缩放和键盘浏览。画布只加载当前需要的缩略图，视频仅在打开预览时播放。按同一模型和请求比较两条路径的交互延迟、H3 耗时、峰值显存和失败情况。兼容表记录设备实测值。[GPUCanvas React 接口](https://github.com/berkantay/gpucanvas/blob/v0.6.0/src/react.tsx) · [GPU 探测](https://github.com/berkantay/gpucanvas/blob/v0.6.0/src/gpu/backend.ts) · [Chrome HTML-in-Canvas](https://developer.chrome.com/blog/html-in-canvas)

前端本地保存缩放、视图位置和选择的渲染方式。模型登记、兼容配置、运行记录、进度及产物由 Rust 持有。画布交互采用稳定的可见焦点、明确的标签与文本状态，拖动和键盘操作即时响应。开启减少动态效果时保留静态状态反馈，缩短或关闭位置与缩放过渡。

## 4. 本机 API 与交付

以下路由是首版提案。模型包、操作、请求和产物仍使用运行时规范中的字段及语义。

| 路由 | 用途 |
|---|---|
| `GET /api/v1/device` | 返回本次服务已选定的实际设备和可用后端配置，供生成面板呈现当前环境。 |
| `GET /api/v1/models` | 返回已登记模型包、兼容配置、操作与参数描述。 |
| `POST /api/v1/assets` | 接收参考素材，校验类型和大小，返回资产 ID。 |
| `POST /api/v1/preflight` | 对同一份生成请求返回预检结果与字段级错误。 |
| `POST /api/v1/runs` | 以 `Idempotency-Key` 关联一次用户提交，通过检查后返回 `run_id`。 |
| `GET /api/v1/runs` 和 `GET /api/v1/runs/{run_id}` | 查询历史和单次运行快照，浏览器刷新后回查。 |
| `POST /api/v1/runs/{run_id}/cancel` | 请求停止该运行，最终状态以查询结果为准。 |
| `POST /api/v1/runs/{run_id}/deliver` | 重试交付已完整保留的产物。 |
| `GET /api/v1/assets/{asset_id}` | 返回受限素材、缩略图或产物。视频支持 Range 读取和拖动进度条。 |

前端先轮询运行快照，仅在活跃任务期间继续查询。模型能力与状态进入页面时读取，提交后的旧响应不得覆盖更新的草稿。开发时由 Vite 代理 `/api/v1`。发行时由只监听回环的 Rust 服务同源提供 API 与 `ui/dist`，静态资源根限定在构建目录，写请求验证来源。

## 5. 实施顺序和验收

| 阶段 | 交付 | 验收 |
|---|---|---|
| 1 · 页面与契约 | 同仓 UI 骨架、三页布局、少量后端样例响应 | 用样例走通创作、模型库、历史。覆盖无模型、设备不支持、缺素材和外部盘重连。 |
| 2 · 图像闭环 | 固定一套文生图配置。接入素材、预检、运行与产物 | 模拟提交回执丢失，重复提交返回原 ID。刷新后按原 ID 恢复。显示实际尺寸、种子和参数。 |
| 3 · H3 与故障恢复 | 文生和首帧图生接入，视频原生播放 | 检查首帧、音轨、取消、断线、进程中断、显存不足及重试交付。已启用的多参考配置另验参考顺序。 |
| 4 · 画布和发布 | GPUCanvas 结果区，双渲染路径，本地打包 | Chrome 和 Safari 完成同一条生成与浏览路径。切换渲染后位置和选择保留。测量冷启动、平移缩放与 H3 同时运行时的显存。 |

验收样例结果和关键操作以 Rust 实际回执为准。首版 UI 可以用样例数据先验证交互。设备兼容、画布性能与 H3 并发显存通过实机记录确认。
